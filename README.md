## 起動

このフォルダで `py -m http.server 8000` を実行し、ブラウザで `http://localhost:8000` にアクセスします。iPhone実機ではHTTPSでの配信が必要です。iPhone Safariから「ホーム画面に追加」でPWA表示を確認できます。

## 実装済み

- 共通UI・4タブ・下部ナビ・ライト／ダーク・セーフエリア対応
- 日用品一覧、固定5カテゴリ、折り畳み、検索、在庫なしフィルタ、在庫あり／なし切替
- 同一カテゴリ内での上下移動、日用品追加・編集、正規化名の重複防止
- 日用品詳細、お気に入り仮登録・順序変更、比較期間の切替、比較単位、メモ
- 同名日用品に対するフォーム内案内と非表示日用品のリスト復帰
- 端末内localStorageでの試作用データ保持と初期化
- PWA manifest / Service Worker による静的アセットのキャッシュ

## 未実装・注意

Google Sheets / GAS、認証、夫婦間同期、IndexedDB、OCR、レシート、家計簿集計、実価格・店舗履歴は未実装。レシート／家計簿／設定の主要機能はプレースホルダーです。

**試作データは正本ではありません。** 保存はこのブラウザの localStorage のみで、別端末に共有されません。実際の家庭データやレシート情報を投入しないでください。

同名の非表示日用品を新たに重複作成する分岐は設けません。登録商品は非表示日用品を戻さず別の日用品へ移動できます。本番ではGAS側の原子的な操作・同時更新制御が必要です。最安値は `—` と表示し、架空の価格は提示しません。

### 確認できた実装範囲
- 静的PWA（`index.html` / `app.js` / `styles.css` / `manifest.webmanifest` / `sw.js`）。**React/TypeScriptではなく素のJavaScriptによる試作**です。後工程での採用・移行方針は別途判断してください。

### 今回の修正
- 日用品追加・編集と比較単位のフォームで変更がある場合、キャンセル時に「変更を破棄／編集を続ける」を表示。入力中のフォームを確認画面に置き換えず保持。
- タッチ長押し並び替えでは、Safariのタッチ識別子をPointer Capture APIに渡さないよう整理。

### 共通UIルール
1. 戻る：詳細から一覧へ。編集画面で未保存の変更があるときだけ破棄確認。キャンセルは保存しない。保存は入力検証後に確定する。
2. 見出しと詳細メニュー：『日用品を編集』『日用品を削除』『お気に入りの管理』『登録商品の管理』『比較単位の設定』を統一。削除は**非表示**であり、商品・購入履歴の削除ではない。
3. 重要操作はラベル付きボタン、補助操作は右上の「⋯」に配置。同じ意味には同じアイコンを使う。主要タップ領域は原則44 CSS px以上。
4. 長押し並び替えは約420 ms、同一カテゴリ内に限定。通常スクロールで意図せず並び替えない。検索・在庫なしフィルタ中は並び替え不可。お気に入りにも同様の長押しを適用。
5. カテゴリ順固定（飲食、キッチン、洗面・風呂、洗濯・掃除、その他）。日用品一覧は在庫情報を中心にし、詳細はお気に入り→全商品最安値→メモ。価格と購入店・購入日は実購入データ導入後に表示。
6. フォント・色・ボタン・余白は共通CSSを使い、iPhoneのセーフエリアとライト／ダークに配慮する。

## 2026-10-17 v1.5 操作感・表示の修正（現行仕様。旧記述に優先）
- 日用品一覧は**高さを抑えた2行バー**（名称／価格要約）。価格は在庫専用の右側領域に入り込まず、バーの**右端**に6px前後の控えめな帯を置く。右側の「あり／なし」ボタン表示は従来のコンパクトな寸法に戻す。

- 価格情報のタブ名は**「商品価格／店頭商品と比較」**。後者は旧「単位価格」モードの置換であり、**別の「店頭と比較」開閉入力欄は削除**。比較用**数量は空欄が初期値**。単位だけ先頭の登録商品の内容量単位を初期値とする。数量と単位は入力／選択完了時に画面へ**自動適用**し、適用・保存ボタンは置かない。画面を離れると値は破棄する。
- **「最安値」と期間切替は、数量・単位の下**に配置。期間は商品価格と店頭商品と比較の両モードで共通。最安値は購入単位の税込通常／割引および登録商品別の換算結果で、価格ごとの店舗名を示す。
- 「商品を登録」は既存商品検索・選択のみの**共通ハーフモーダル**として価格情報に重ねる。登録先は表示中の日用品。モーダル内の「新しい商品を作成」は廃止（誤った登録先を連想させない）。
- 登録商品一覧も**左スワイプで編集・登録解除**し、長押しで順序を変更する。商品行の旧「⋯」は不要。確認付き解除は商品のデータや履歴自体を消さない。
- iPhone Safariの実機で、固定座標ドラッグ・横スワイプ中の操作露出・小さな在庫ボタン・画面端タッチ・文字省略を検証する。試作の価格・店舗は明示したサンプルであり、実価格／レシート／値札の接続ではない。

## 2026-10-17 v1.6 商品登録・換算表示・ジェスチャー修正（現行仕様）
- 商品登録ハーフモーダルは**検索結果件数で高さを変えない**。共通フォーム部品 `UI.formField({type:'search'})` を使用し、検索欄固定・候補部分だけ縦スクロールにする。未登録商品の候補を先、既に日用品に登録先がある商品は**末尾**に置く。現在の日用品に登録済みの候補は選択不可、他の日用品の登録商品は確認後に付け替え可能。
- 日用品一覧・価格情報では「タップで開く」「入力すると自動反映する」といった**操作すれば分かる説明文を常設しない**。サンプル価格、同期未接続など誤解防止の注意書きだけ残す。
- 「店頭商品と比較」は数量と単位をその場で適用。数量は初期空欄、単位は先頭商品と一致。**最安値見出しに「900mLあたり」などの換算対象を添え、登録商品それぞれの通常／割引価格のラベルにも同じ数量・単位を示す**。数量未入力時は勝手に初期値を当てはめない。
- 長押しのドラッグ複製行は、通常バーと同じ**角丸・文字の太さ・余白・レイアウト**を維持する。ドラッグゴーストに以前の `display:flex`・追加パディング・強制文字ウェイトが適用されないようにする。
- スワイプ行の識別には共通の `swipeRowId(row)` を使い、日用品ID／商品IDのどちらも扱う。対象の1行以外は移動・開閉させない。
- iPhone実機で検索フォーカス時のキーボード、検索結果スクロール、長押し中の書体、商品ごとの単独スワイプを確認する。自動テスト成功だけでは実機の操作感を保証しない。
